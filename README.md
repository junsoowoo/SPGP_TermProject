# Drag and Destroy

 1. 프로젝트 소개

**Drag and Destroy**는 Android 기반 2D 슈팅 디펜스 게임입니다.
플레이어는 왼쪽의 전투기를 조작하여 적의 공격을 피하고, 화면을 드래그하여 임시 포탑을 설치해 몰려오는 적을 처치합니다.

기본적인 슈팅 게임 구조에 디펜스 요소를 결합했습니다. 일반적인 슈팅 게임은 플레이어의 이동과 발사에 집중하지만, 이 게임은 드래그 경로를 따라 포탑을 설치하고, 설치 에너지를 관리하면서 적을 막는 것이 핵심 차이점입니다.

 3. 게임 조작 방법

플레이어 이동
왼쪽 아래 조이스틱을 사용하여 전투기를 이동합니다.

포탑 설치
화면을 드래그하면 드래그 경로를 따라 임시 포탑이 설치됩니다.
포탑 설치에는 에너지가 필요하며, 에너지가 부족하면 설치할 수 없습니다.

포탑 선택
스테이지 선택 화면에서 Basic 포탑과 Rapid 포탑 중 하나를 선택할 수 있습니다.

상점 이용
스테이지 클리어 후 상점으로 이동하여 골드를 사용해 능력치를 강화할 수 있습니다.

일시정지
게임 중 오른쪽 위 버튼을 눌러 일시정지할 수 있습니다.

 7. 목표 변경 내용과 이유

초기 목표는 플레이어가 이동하며 총알을 발사하는 단순 2D 슈팅 게임이었습니다.
그러나 단순 슈팅만으로는 게임의 차별성이 부족하다고 판단하여, 2차 개발부터 드래그로 포탑을 설치하는 디펜스 요소를 추가했습니다.

변경된 목표
* 단순 슈팅 게임에서 슈팅 + 디펜스 게임으로 변경
* 플레이어 직접 공격뿐 아니라 포탑 설치 전략 추가
* 드래그 조작을 핵심 시스템으로 변경
* 스테이지 선택과 상점 시스템 추가
* 최종 보스 스테이지 추가

변경 이유는 모바일 환경에서 터치 조작을 더 적극적으로 활용하기 위해서입니다.
단순히 버튼으로 발사하고 이동하는 방식보다, 사용자가 직접 드래그한 경로에 포탑이 설치되는 방식이 게임의 핵심 재미를 더 잘 만들 수 있다고 판단했습니다.

 12. 아쉬운 점


1. 스테이지별 차별화가 충분하지 않습니다.
스테이지마다 적의 체력, 이동 속도, 공격 주기, 보상은 다르지만, 지형이나 특수 패턴처럼 눈에 띄는 차이는 부족합니다.

2. 보스 등장 연출이 단순합니다.
보스 스테이지에서 보스가 등장하고 HP바가 표시되지만, 등장 애니메이션이나 경고 연출이 충분하지 않습니다.

3. 사운드 품질이 전문적인 게임 사운드에 비해 부족합니다.
효과음을 직접 제작하고 적용했지만, 실제 상용 게임 수준의 믹싱이나 음색 조정까지는 부족했습니다.

4. 해상도 대응이 완벽하지 않습니다.
기준 해상도에 맞춰 UI를 배치했기 때문에, 다양한 화면 비율의 기기에서 완전히 동일하게 보인다고 보장하기 어렵습니다.

5. 번째로 밸런스 조정이 충분하지 않습니다.
게임이 진행되면서 적의 체력, 포탑 데미지, 상점 가격, 코인 보상 등이 적절하게 맞아야 하지만, 충분한 플레이 테스트를 하지는 못했습니다.

 14. 해결하지 못한 문제와 어려웠던 점

* 일부 사운드의 품질이 만족스럽지 않은 점
* 스테이지별 개성이 부족한 점
* UI 배치가 특정 해상도 기준에 의존하는 점
* 포탑과 적의 밸런스가 완벽하지 않은 점

프로젝트를 진행하면서 가장 어려웠던 점은 게임 구조가 커질수록 파일 간 의존성이 복잡해지는 것이었습니다.
Scene, Object, Data, Util 패키지를 나누어 관리했지만, 기능이 늘어나면서 import와 리소스 연결이 꼬이는 문제가 있었습니다.

또한 포탑 설치 방식처럼 기존 수업 예제에 없던 기능을 만들 때, 드래그 경로 처리와 설치 간격 계산, 에너지 소비 방식을 맞추는 것이 어려웠습니다.

마지막으로 배경 이미지를 사용할 때, 분명 수업 시간엔 한 장으로 자연스럽게 연결했지만 직접 해보니 어려워 결국 해결하지 못하고 이미지를 반전시켜서 다시 출력하는 방식으로 수정했습니다.

 15. 수업에 대한 내용

이번 수업에서 기대한 것은 기존에 관심있었던 스마트폰 게임에 대한 이해를 얻어가는 것이었습니다.
프로젝트를 통해 Scene 구조, Sprite 출력, 게임 루프, 터치 처리, 충돌 처리, 리소스 적용 등 게임 제작에 필요한 기본 구조를 배울 수 있었습니다.

얻은 것은 단순히 화면에 이미지를 띄우는 수준이 아니라, 여러 Scene을 연결하고 게임 오브젝트를 관리하며 하나의 완성된 게임 흐름을 만드는 경험입니다.
특히 직접 기획한 시스템을 코드로 구현하면서, 기능이 늘어날수록 구조를 정리하는 것이 중요하다는 것을 알게 되었습니다.

얻지 못한 점과 변화하면 좋을 점은 수업 시간에 이미 만들어진 예제나 구조를 따라가는 내용이 많아 직접 무언가를 처음부터 만들어 간다는 몰입감은 조금 떨어졌다는 점입니다.
더 좋은 수업이 되기 위해서는 Kotlin 개념 위주의 과제보다는, 수업 시간에 배운 Scene 전환, Sprite 출력, 충돌 처리, 터치 입력 같은 내용을 직접 응용해보는 과제가 있으면 좋겠다고 생각합니다. 당연히 4학년 수업이라 과제 부담을 줄여주신 것에 감사하게 생각합니다. 그래서 이 강의는 3학년 과정에 배치되면 더 여유 있게 프로젝트를 발전시킬 수 있을 것 같다고 생각합니다.
